# Hell Harbor Entertainment Physical Media Shop

Secure storefront scaffold for direct-to-fan CDs, cassettes, vinyl and other Kunaki-manufactured releases.

## Production architecture

- `hellharbor.com`: main Hell Harbor Entertainment site.
- `shop.hellharbor.com`: commerce surface on Cloudflare Workers Static Assets.
- Stripe Checkout: hosted payment UI.
- Cloudflare D1: order and fulfillment state.
- Kunaki XML service: live shipping quotes, manufacturing orders, order status and tracking.

## Required order flow

1. Customer builds a cart from server-authoritative SKUs and HHE prices.
2. Backend sends destination + Kunaki ProductIds + quantities to Kunaki ShippingOptions.
3. Customer selects one of Kunaki's returned shipping methods.
4. Backend revalidates cart and shipping, then creates a Stripe Checkout Session.
5. Customer enters payment details on Stripe-hosted Checkout.
6. Stripe sends a signed `checkout.session.completed` webhook.
7. Backend verifies the webhook and confirms `payment_status=paid`.
8. Backend reconciles Stripe's final shipping country/state/postal code against the destination used for the Kunaki quote.
9. Only after successful payment verification does the backend send the manufacturing order to Kunaki.
10. A scheduled job polls Kunaki OrderStatus and stores status/tracking updates.

## Security rules

Never place these values in browser JavaScript, GitHub Pages, committed config files, query strings generated by client code, or public repository history:

- Stripe secret key
- Stripe webhook signing secret
- Kunaki publisher user ID
- Kunaki publisher password

Store them only as encrypted deployment secrets on the server-side runtime.

The browser may receive only:

- public SKU
- product title / format / artwork
- HHE retail price
- live shipping quote
- Stripe-hosted checkout URL
- non-sensitive fulfillment/tracking status

The server remains authoritative for HHE pricing and maps public SKUs to Kunaki ProductIds.

## Product setup

Publish each physical release in Kunaki first. The fulfillment APIs do not publish titles. Every sellable catalog entry needs its Kunaki 10-character ProductId and HHE retail price in `src/catalog.js` before `active` is set to `true`.

The starter catalog is intentionally inactive so no placeholder product can be sold accidentally.

## Cloudflare setup

Create the D1 database and replace the `TBD` database ID in `wrangler.jsonc`:

```bash
npx wrangler d1 create hell-harbor-media-shop
npx wrangler d1 execute hell-harbor-media-shop --remote --file=./schema.sql
```

Configure deployment secrets through Cloudflare's encrypted secret store, not the repository.

Keep `KUNAKI_MODE` set to `Test` until the complete Stripe-to-Kunaki flow has passed end-to-end testing.

## Stripe configuration

Use Stripe-hosted Checkout rather than custom card inputs. The final backend should create Checkout Sessions server-side and register a webhook at:

```text
https://shop.hellharbor.com/api/stripe/webhook
```

Subscribe at minimum to:

- `checkout.session.completed`
- `checkout.session.async_payment_succeeded`

The fulfillment handler must be idempotent so a replayed Stripe event cannot create a duplicate Kunaki order.

## Kunaki account funding

Kunaki API orders can remain pending until the publisher account is funded. For automatic customer fulfillment, maintain a prepaid Kunaki balance sufficient to cover manufacturing and shipping charges.

## Ko-fi

Ko-fi is appropriate for donations/support and can notify a backend through payment webhooks. It is not the primary cart payment engine in this architecture because its API is webhook-oriented rather than a general dynamic checkout-session API.
